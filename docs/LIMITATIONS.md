# Limitations

These apply to every result in this repository.

## Data
- **Simulated data.** C-MAPSS is generated by a physics-based simulator with injected degradation. Real engines differ in noise, sensor faults, maintenance history and failure modes. Nothing here shows the methods work on real engines.
- **Run-to-failure assumption.** The supervised RUL pipeline needs trajectories that end in failure (or a defined threshold crossing). Machines with few or no failures need other methods; censored assets are currently excluded, not modelled.
- **Second machine type is a demonstration.** The battery experiment uses four cells, a project-defined end of life (1.5 Ah, not NASA's 1.4 Ah), leave-one-cell-out validation and no test set. It shows the pipeline runs on different signals; it does not show a model that works on batteries in general.
- **No model transfers by default.** The pipeline and method are reusable across machines; a trained model is not. Cross-subset transfer results in `reports/transfer.md` show how much accuracy is lost when train and target conditions differ.

## Modelling and evaluation
- **Official test sets are small.** One true RUL per test asset (100-259 points), so confidence intervals are wide and models whose intervals overlap are not separable.
- **Capped target.** Models are trained on RUL capped at 125 and cannot predict beyond it; this dominates error on test assets with larger remaining life (27% of FD004 test assets). Prediction intervals are for the capped target only.
- **Light tuning.** Hyperparameters are fixed defaults; no search was run. The deep-learning comparison (GRU/LSTM) was done on FD001 only, with one network size and no tuning, so it does not show that deep learning is generally worse.
- **Single seed or fold assignment in places.** Cross-validation uses one fold assignment (seed 0); transfer and interval experiments use one model seed.
- **Development vs test metric differences.** The development "cut" metric is not distributed like the official test (see `reports/gap_diagnostics.md`); use test numbers with their confidence intervals for the benchmark and development numbers only for relative comparison.

## Warnings, anomalies, intervals, explanations
- **Thresholds are experimental.** The 30/15-cycle warning levels are illustrative operating points, not maintenance standards. The cost of a missed failure versus a false alarm is application-specific and was not modelled.
- **No calibrated failure probability.** Predicted RUL and alert state are not probabilities; calibration was not evaluated.
- **Anomaly detection has no real labels.** C-MAPSS has no labelled anomalies. Accuracy is measured only on synthetic injected faults, which are single-signal, scaled by healthy variance, and may not resemble real faults. Per-step detectors cannot detect stuck sensors.
- **Interval coverage is marginal.** Conformal intervals are valid on average over the evaluation distribution but under-cover mid-life RUL values and over-cover the extremes; they assume calibration and evaluation assets are exchangeable.
- **SHAP is not causal.** Attributions describe one model's behaviour; correlated signals share credit unpredictably, and importance rankings differ between models.

## Engineering
- **Not production-ready.** No online data ingestion, monitoring, drift detection, security or deployment hardening exists. The system is a research and demonstration platform.
- **Performance figures are from one CPU laptop** (see the hardware recorded in each run record).
